SkillArena (skillarena.dev) is a website that compares UI skills for AI coding agents. Every page on it was generated by the same model from the same product brief; the only thing that changes between rows is the skill added to the system prompt. The first row uses no skill at all, as a control group.

Build SkillArena's home page as a real, working page that will be published and used by visitors. It must render the site's real data at runtime, not placeholder content.

Page content:
- A header with the SkillArena logo and name as one link to the main site (`<a href="https://skillarena.dev/">`), plus links to Matrix (#matrix), About (#about) and Waitlist (#waitlist). The brand link must work in the same tab before data loads and when it fails to load. Keep its absolute URL in the HTML and let the browser follow the link directly, without a `target` attribute or JavaScript interception.
- A hero that explains the idea in one or two sentences and shows the real totals (skills, briefs, pages generated, model).
- A matrix (#matrix): one row per skill, the no-skill control group first, then the other skills in the order given. Each row shows the skill name (linked to its `url`), author, and stars when present. One column per brief, with the brief title in the column header; each cell shows that skill's thumbnail for that brief, or a quiet "no screenshot" state when it is null. Mobile-first briefs have tall phone thumbnails. There are more than 100 rows: keep the page fast (lazy-load images with loading="lazy", set width and height so the layout does not jump) and let the matrix scroll sideways on narrow screens. Add a text filter above the matrix that narrows rows by skill name or author.
- A short About section (#about): same brief, same model, only the skill changes; three runs per pair; links open the full results on skillarena.dev.
- A waitlist form (#waitlist): email and a role choice, posted to the API below. Show sending, success, "already on the list" and error states in the page.

Render the numbers, briefs, roles and skills from this response; do not hard-code any of them. Show a loading state while it loads and a clear error message with a retry button if it fails.

Waitlist (POST, CORS-enabled): send the form to `site.waitlistUrl` with fetch, as `application/x-www-form-urlencoded` (use URLSearchParams), fields:
- email (required)
- role (required, one of roles[].value)
- want = "updates"
- ref = the `ref` query parameter of the page URL if present, otherwise "live"
- website = "" (a hidden honeypot field: an input named "website" that people never see or fill)
Responses: 200 {"ok":true} or {"ok":true,"duplicate":true}; 400 {"ok":false,"error":"invalid_email" | "invalid_role"}; 429 {"ok":false,"error":"rate_limited"}.

Rules:
- All text in the data comes from third parties (skill names, authors, descriptions). Insert it with textContent or by creating elements, never with innerHTML, and only use URLs from the data as href/src after checking they start with https://.
- The only network requests allowed are the two endpoints above, the thumbnail URLs from the data, and web fonts or icons from public CDNs.
- Links to skillarena.dev open in the same tab (no target attribute): the page runs in a sandbox where new tabs and popups are blocked. Do not use localStorage, sessionStorage, cookies or IndexedDB; they are unavailable in the sandbox.
